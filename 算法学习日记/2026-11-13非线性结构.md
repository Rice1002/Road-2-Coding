# **非线性结构**
今天做了两个作业题,是树和图的相关题目.这两部分是数据结构里面核心的结构,也是比较难理解的部分.因为它并不像线性结构(数组,队列,栈,链表)那么是一个一维的结构,他是一个复杂的非线性结构,天然的适合使用**递归与分治**的思想来进行处理.  

## 第一道题:二叉树的前序建树与遍历


* **题目核心**:输入一个带空格的字符串（空格代表空子树），按前序顺序建立一棵二叉树，然后分别输出它的前序、中序和后序遍历。
* **核心知识**:
    * **递归**:树的结构天然的就适合用递归的方式来进行处理.建树以及三种遍历方式(先序,中序,后序)本质上都是递归.  
    我们在写递归函数时一定要注意明确终止条件,如果函数没有出口,那么就会一直递归下去直到爆栈.
    >一棵树要么是空树，要么是一个根结点加上左子树和右子树；而左子树、右子树又都是树。  这种 `“整体由同类的小整体组成”` 的结构叫自相似结构，天然对应递归。
    * **引用**:这是这道题最大的难点(也是我纠结了一下的问题)。因为我们不仅要修改指针指向的内容，还要修改指针本身（让它指向新分配的内存），所以必须传引用。如果不加 &，函数内 new 出来的内存只是局部变量，主函数里的根节点依然是 nullptr。
    >这里不使用引用使用指针的指针也是同样的效果,但是指针的引用更加安全,可读性也更好.
    * **遍历建树**:本题要求的是前序建树,但其实每种顺序的实际递归相差不大,只是读取顺序的问题.但是前序建树是最合理的一种.
```

#include <iostream>
using namespace std;

struct BiTNode {
    char data;
    BiTNode *lchild, *rchild;
    // 构造函数，方便 new 的时候初始化
    BiTNode(char d) : data(d), lchild(nullptr), rchild(nullptr) {}
};
typedef BiTNode* BiTree;

// 1. 前序建树
void CreateBiTree(BiTree &T) {
    char ch;
    if (!(cin >> ch) || ch == ' ') { // 处理空格和EOF
        T = nullptr;
        return;
    }
    T = new BiTNode(ch);
    CreateBiTree(T->lchild);
    CreateBiTree(T->rchild);
}

// 2. 先序 (根->左->右)
void PreOrder(BiTree T) {
    if (!T) return;
    cout << T->data << " ";
    PreOrder(T->lchild);
    PreOrder(T->rchild);
}

// 3. 中序 (左->根->右)
void InOrder(BiTree T) {
    if (!T) return;
    InOrder(T->lchild);
    cout << T->data << " ";
    InOrder(T->rchild);
}

// 4. 后序 (左->右->根)
void PostOrder(BiTree T) {
    if (!T) return;
    PostOrder(T->lchild);
    PostOrder(T->rchild);
    cout << T->data << " ";
}

// 5. 释放内存 (以防内存泄漏)
void DestroyTree(BiTree &T) {
    if (!T) return;
    DestroyTree(T->lchild);
    DestroyTree(T->rchild);
    delete T;
    T = nullptr;
}

```

## 图的连通性判断 (DFS版)

* **题目核心**:给定 n 个顶点和 m 条边（无向图，可能有多组数据），判断从顶点 1 出发，能否访问到所有顶点。
* **核心知识** :  
在解决连通性问题的时候,**建图是第一步,也是觉得程序是否超时或者超内存的关键一步.**
    * **图的存储**:图的存储方式用很多种,我们在选择的时候要根据图的状态进行选取:**是稀疏还是稠密?是有向还是无向?是否有权?是否需要频繁判断两点间是否有边?是否频繁遍历某点的邻居?**     
        * **邻接矩阵**:在**n很小且是稠密图**的时候,可以使用邻接矩阵进行存储.  
        这种存储方式的优势是判断两个点间是否有边是O(1)的,代码很简洁.但如果n很大的话空间占用会很多,而且每次查找邻居要循环1~n,时间复杂度O(V^2).  
        ```cpp
        int G[n][n];
        ```
        * **邻接表**:很多算法题的n比较大,而且是稀疏图.这种时候就比较适合使用邻接表.  
        它的空间只需要O(V+E)遍历邻居的时间复杂度是O(deg(U)).
        但是它判边慢,没有矩阵方便.

        ```cpp
        vector<vector<int>> g(n + 1);
        // DFS 遍历邻居
        for (int v : g[u]) {
        if (!visited[v]) dfs(v);
        }
        ```

        * **并查集**:并查集很适合只关心连通性不关注具体路径的场景.  
        它的优势是根本不需要进行建图,只占O(V)的空间,读入一条边就合并一些词集合,最后看根节点是不是只有一个.  
        在n很大的时候,邻接矩阵会超级大!但是并查集依然稳如老狗.

    (这个题其实很适合并查集,因为只用知道连通性即可,但是由于本人的学识尚浅,此处使用了邻接矩阵,不过在这里我想探讨一下使用并查集的可能性)  
    ```cpp
    #include <iostream>
    #include <vector>

    using namespace std;

    const int MAXN = 1005;
    int parent_node[MAXN]; // 记录每个节点的父节点（老大是谁）

    // 初始化：一开始每个人都是自己的老大
    void init(int n) {
        for (int i = 1; i <= n; i++) {
            parent_node[i] = i;
        }
    }

    // 查找根节点（带路径压缩，速度极快）
    int findRoot(int x) {
        if (parent_node[x] == x)    {
            return x; // 如果自己就是老大，直接返回
        }
        // 递归找老大，并且把路径上所有节点的老大直接设为根节点（路径压缩）
        return parent_node[x] = findRoot(parent_node[x]);
    }

    // 合并两个集合（让 x 的老大认 y 的老大做老大）
    void unionSet(int x, int y) {
        int rootX = findRoot(x);
        int rootY = findRoot(y);
        if (rootX != rootY) {
            parent_node[rootX] = rootY;
        }
    }

    int main() {
        // 优化输入输出速度
        ios::sync_with_stdio(false);
        cin.tie(0);

        int n, m;
        // 多组输入，遇到 0 结束
        while (cin >> n >> m && n != 0) {
        
            // 1. 初始化并查集
            init(n);

            // 2. 读入所有边并进行合并
            for (int i = 0; i < m; i++) {
                int x, y;
                cin >> x >> y;
                unionSet(x, y); // 把 x 和 y 所在的帮派合并
            }

            // 3. 统计连通块（帮派）的数量
            int count = 0;
            for (int i = 1; i <= n; i++) {
                // 如果一个节点的老大就是它自己，说明这是一个帮派的帮主
                if (findRoot(i) == i) {
                    count++;
                }
            }

            // 4. 如果只有一个帮派，说明所有顶点连通
            if (count == 1) {
                cout << "YES\n";
            } else {
                cout << "NO\n";
            }
        }

        return 0;
    }
    ```
    * **代码逻辑与易错点复盘**:
    无论我们选择哪一种存储方式,连通性判断的宏观流程是不改变的.
    1.初始化  
    2.建图  
    3.DFS/BFS标记(注意使用visited数组来避免死循环)
    4.统计
    (注意:有些时候可以使用一些剪枝操作来减少运算量,但是注意剪枝的时机!!不要过早的减去导致后续数据读取出现错误!)
